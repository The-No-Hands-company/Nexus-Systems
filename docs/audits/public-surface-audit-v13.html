Part 1 — Public surface

Everything reachable as an anonymous visitor on 13 October 2026.

The core holds. The sign-in gate refused every anonymous probe on every app host. All traffic enters through one proxy. The serious problems were at the edges: user-deployed websites shared the sign-in domain, and nobody new could get into the platform. Both are fixed; the architectural same-site problem is mitigated with Sec-Fetch-Site enforcement while a PSL submission runs in the background.

Fixed on audit day (13 Oct)

F-1CriticalFixed · 4531da9f

User-deployed sites received every visitor's sign-in session

Found
Sites on *.tnhc.dev share the parent domain with the session cookie (Domain=.tnhc.dev). The proxy forwarded the visitor's whole Cookie header to Hosting. Any signed-in user with a dynamic site could collect the session of every signed-in visitor.
Fix
User sites get no Cookie or Authorization from the request, and any Set-Cookie with a Domain attribute is stripped from the response.
F-2HighFixed · 7872c42f, d80a2b58

Nobody without an account could get in

Found
Request-access and claim pages were behind the sign-in gate. Invites had an API and no page.
Fix
auth.tnhc.dev/request, /claim and /join: script-free forms, strict CSP, no caching, length caps, rate limits.
F-3MediumFixed · 8e511a37

The proxy weakened stricter referrer policies

Fix
The proxy policy is now a floor; upstreams that chose something stricter keep it.

Fixed after the audit

O-1HighMitigated · 2171f91b · PSL pending

Found
JavaScript on any user site can forge credentialed requests to app hosts because they share the same eTLD+1.
Mitigation
Proxy checks Sec-Fetch-Site: any same-site mutation to an app host is rejected 403. PSL submission is the architectural fix.

Part 4 — File upload integrity

Path traversal and MIME validation across all upload handlers. 16 October 2026.

2high, fixed
0open

Findings

U-1HighFixed · d3a62fc (Chat) + 8401f2d9 (proxy)

SVG uploads enabled XSS on the session-cookie domain

Found
image/svg+xml was in the chat attachment allowlist with no sanitization. MinIO serves files verbatim. Files are accessed via storage.tnhc.dev, a subdomain of tnhc.dev where the session cookie's Domain=.tnhc.dev applies. A browser rendering an attacker-supplied SVG on storage.tnhc.dev would execute its JavaScript with full access to the session cookie.
Attack path
Authenticated attacker POSTs SVG with <script> → stored in MinIO → shares presigned URL → victim clicks → JS executes on storage.tnhc.dev → reads document.cookie → session stolen or credentialed XHR to any app.
Fix — Chat
Removed image/svg+xml from the is_allowed_content_type() allowlist in uploads.rs. Comment explains the cookie-domain reasoning.
Fix — Proxy
Added forceAttachmentForStorage(): when storage.tnhc.dev returns a scriptable Content-Type (SVG, HTML, JS, XML, XHTML), the proxy forces Content-Disposition: attachment — defense-in-depth so any future path-through still downloads instead of rendering.
U-2HighFixed · d3a62fc

Emoji upload accepted attacker-controlled Content-Type verbatim

Found
emoji.rs read the Content-Type field from the multipart header and stored it to MinIO without any allowlist check. Attacker could supply text/html; MinIO would serve the file as HTML on storage.tnhc.dev, giving full HTML/JS execution in the shared cookie domain — a higher-impact variant of U-1.
Fix
Added a strict allowlist in the "image" multipart branch before reading the bytes: only image/png, image/gif, image/webp, image/jpeg, image/avif accepted. Any other type returns 422 immediately.

Upload handlers — clean

stickers.rsContent-Type derived from validated type field (png/apng/lottie → fixed media types). Attacker-supplied type field rejected before storage.
uploads.rs (general attachments)Magic-byte sniffing confirms declared MIME; family mismatch rejected. Filename sanitized (strips path separators, NTFS ADS, control chars). SVG now removed from allowlist.
Nexus-Hosting deploy.tsHTML/JS/CSS are intentional in the allowlist (user sites deploy full web content). Cookie isolation at the proxy layer prevents user sites from reading ecosystem session cookies from requests. sanitizeFilePath() normalizes then strips leading ../ traversal sequences.
Rate limitingPer-user and per-tag (IP fallback) limits on all upload endpoints. Content-Type checked before reading bytes (early-reject).
File storageAll files stored in MinIO, never on the origin filesystem. Served via 24-hour presigned URLs, not served directly from tnhc.dev.
