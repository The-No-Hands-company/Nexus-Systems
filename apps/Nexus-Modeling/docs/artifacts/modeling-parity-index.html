On its FIRST run it found a real bug: flipEdge/splitEdge/insertEdgeVertex/collapseEdge range-checked their half-edge index but did NOT reject a TOMBSTONED (dead, face==kInvalid) half-edge — and since edgeCount() includes dead edges with no public liveness query, iterating [0,edgeCount()) after any mutation corrupted live topology ("live edge has dead/invalid prev"). Fixed with a liveness guard on each op (refuse dead input → the succeed-or-refuse-never-corrupt contract). This closes the "hand-picked tests only" gap — the kernel now hunts its own unknown-unknowns. Full suite 2266 pass / 5 GPU-skip / 0 fail. Next: PHASE T — migrate the ~180 scattered epsilons onto the scale-aware Tolerance module.

    PHASE T — scale-aware boolean seam weld fixes a REACHABLE large-model leak — first systematic tolerance migration (GAP-T: ~180 scale-blind epsilons), and it closed a genuine reachable scale bug: the FLAGSHIP mesh boolean was watertight at unit scale but LEAKED at scale ≥ 100. Root cause — the seam-stitch weldCoincidentVertices(1e-5f): at coordinate magnitude M the two independently-computed copies of a seam vertex differ by ~M·1e-6 (float32 precision), so a fixed 1e-5 weld can't merge them on large models (probe: diagonal-offset boxes bnd=0 at scale 1 but bnd=8–12 at scale 100/5000/100000). Fix: derive the weld tolerance from the model's coordinate span L via Tolerance{}.at(L) = max(1e-5, 1e-6·L) — preserves unit-scale EXACTLY (the 1e-5 floor dominates until L>10, so existing tests are byte-for-byte unchanged) and grows in proportion for large models. Now watertight + volume-exact across 1 → 100000× (new test SeamWeldIsScaleAwareAcrossOrdersOfMagnitude). DISCIPLINE NOTE: also investigated MeshTransform::normalMatrix's scale-factor epsilon and deliberately LEFT it — its differing regime (micro scale factors) is where Mat4::inverse() ALSO fails, so migrating it fixes nothing reachable; don't migrate an epsilon whose change you can't prove improves a real result. Only METRIC tolerances touched; no exact/combinatorial path changed. Full suite 2267 pass / 5 GPU-skip / 0 fail. (Also, at the user's request: added mold/lld fast-linker auto-detection to CMake — link 14.1s→10.8s — for faster loop iteration.)

    PHASE R — fix a heap-corruption bug the extended fuzzer found + full HEM liveness sweep — closing the inc55 dead-index class: extended test_KernelFuzz to exercise ALL 13 index-taking half-edge ops in random sequences. Audit result: the edge-loop ops and all face ops already guard their index for liveness, and bevelVertex/connectVertices refuse gracefully — but the fuzzer surfaced a MORE SEVERE, distinct bug in insertEdgeLoop: its Phase 1 continue-skips loop edges with boundary/dead twins, so splitEdges/newVerts can be SHORTER than loop — yet Phase 2 iterated [0, loop.size()) and indexed splitEdges[i]/newVerts[i] OUT OF BOUNDS, then wrote through the garbage indices = a reachable HEAP CORRUPTION / double-free (observed as an actual crash) whenever the loop contains a boundary edge (e.g. after a prior op opened one). Invisible to the single-op property tests because a clean manifold mesh never skips in Phase 1. Fixed to iterate splitEdges.size(). Also added public isLiveEdge/isLiveFace queries — the root reason the whole class is reachable is that edgeCount()/faceCount() include tombstoned slots with no way to skip them. The all-ops fuzz now runs 2400 random mutations with ZERO corruption; a new liveness-query test pins the succeed-or-refuse-never-corrupt contract. Full suite 2268 pass / 5 GPU-skip / 0 fail. LESSON: the fuzzer keeps paying off — this was a memory-safety bug, strictly worse than a topology violation, that no hand-picked single-op test would ever have reached.

    PHASE T — scale-INVARIANT triangle degeneracy fixes small-model boolean failure — second tolerance migration, applying the inc56 discipline (probe reachability BEFORE migrating). isDegenerateTriangle (in the BooleanOperation triangulate/validate path) compared |cross|² to a FIXED 1e-16; since |cross|² = (2·area)² scales as length⁴, that absolute floor wrongly flags valid sub-millimetre triangles. PROBED: BooleanOperation::compute(Union) on valid boxes returns valid=0 / 0 faces at scale ≤ 5e-5 (0.05 mm) — the small-scale twin of the inc56 large-scale weld leak. FIX: a scale-INVARIANT test — area vs a relEps-fraction of the triangle's OWN largest edge² (|cross|² ≤ (relEps·maxEdge²)², i.e. the thin dimension is below a scale-relative linear tolerance), needing no bbox plumbing; relEps=1e-8 reproduces unit-scale exactly. Result: the same box boolean is valid + non-empty from 0.05 mm to 5 km, unit scale unchanged, and a genuinely collinear triangle is still rejected at every scale (2 new tests). No combinatorial/exact path touched. Full suite 2270 pass / 5 GPU-skip / 0 fail.

    PHASE R — malformed-INPUT fuzz battery + fixes a non-finite leak it found — pointed the harness at the one unexercised class: adversarial mesh INPUTS. A deterministic battery of malformed archetypes (non-manifold edge, open shell, degenerate/collinear, duplicate verts, self-intersecting, NaN/±Inf positions, empty/single-tri) fed through EVERY public entry point — both mesh booleans (both operand orders), BooleanOperation::compute/validateMesh, MeshTopologyValidation, MeshRepair::repairAll, MeshVertexWeld::weld, HalfEdgeMesh::fromMesh. Result: NO crash / heap corruption anywhere — but it caught a real gap: MeshVertexWeld::weld and MeshRepair::repair(All) PROPAGATED non-finite (NaN/±Inf) positions into their output, unlike the boolean (which rejects → empty). Silently emitting "welded"/"repaired" NaN geometry is a footgun for downstream consumers. FIXED to match the kernel's non-finite-rejection convention: weld rejects (→ empty), repair declines (→ ok=false, mesh unchanged). The battery now asserts booleans/weld always produce finite output, repair succeeds-finite OR ok=false, and validate/fromMesh never crash. Full suite 2271 pass / 5 GPU-skip / 0 fail. That is now THREE consecutive fuzz-driven finds (2 HEM corruptions, 1 non-finite leak) plus 2 probe-driven scale bugs — the "build the fuzzer first" bet keeps compounding.
