# Nexus Maturity Matrix

## Levels

| Level | Meaning | Exit evidence |
|---|---|---|
| L0 | Concept | Problem, user, and product owner are identified |
| L1 | MVP | One end-to-end user journey works locally |
| L2 | Usable | Core journeys work, errors are explicit, and the app has a maintained backlog |
| L3 | Production | Production deployment, release gate, rollback path, and changelog are established |
| L4 | Feature complete | PRD P1 scope is complete and core quality targets are met |
| L5 | Enterprise ready | Operational, security, accessibility, and recovery expectations are documented and routinely evidenced |

## Initial core cohort

Current levels are governance baselines, not marketing claims. They must be
reassessed at each quarterly review using release evidence.

| Product | Baseline | Target before new-app work | Primary gap |
|---|---:|---:|---|
| Dashboard | L3 | L4 | Unified notifications and product-release visibility |
| Mail | L3 | L4 | Lifecycle, search, and abuse-handling features |
| Calendar | L2 | L4 | Complete event lifecycle and notifications |
| Chat | L3 | L4 | Reliable health reporting and product backlog completion |
| Hosting | L3 | L4 | Product acceptance evidence for core hosting journeys |
| Identity and Kernel | L3 | L4 | Auditable cross-app sessions and release controls |

Files and Docs are excluded from this matrix until they qualify as functional
products.
